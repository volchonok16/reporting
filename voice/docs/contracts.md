# Контракты данных и API

Этот документ фиксирует границы между интерфейсом, API, импортерами и
бизнес-логикой. Номера во всех контрактах являются строковыми
идентификаторами.

## Каноническая модель

```json
{
  "aNumber": "79299994464",
  "bNumbers": ["79152671935", "79104627540"],
  "firstSeenOrder": 1
}
```

Инварианты:

- `aNumber` и каждый элемент `bNumbers` — непустая строка;
- дробные и отрицательные значения запрещены;
- пробельные символы внутри, до или после номера запрещены и не удаляются
  автоматически;
- порядок A и B равен порядку первого появления;
- пустой B в raw-строке становится копией A;
- повторы B по умолчанию удаляются с сохранением первого появления;
- связка без B не сериализуется;
- одна связка A порождает ровно одну строку результата.

Допустимый номер соответствует `^\+?[0-9]+$`. Региональная нормализация,
замена `8`/`7` и удаление `+` не выполняются.
Перед формированием итогового CSV и при изменении мастер-файла дополнительно
проверяется, что опорный номер и каждый АОН не содержат пробелов и начинаются с
`7` (ведущий `+` при проверке не учитывается). Ошибка содержит исходную строку
и тип номера;
автоматической замены `8` на `7` нет.

## Шаблон результата

Заголовок:

```text
order=cap_idp_location_number&CAP_DRN_CLD&CAP_DRN_CLD_BCD&cap_idp_calling_party_number
```

Настройки по умолчанию:

```json
{
  "regionCode": null,
  "firstBMarker": "4:4",
  "nextBMarker": "4",
  "weight": "1",
  "encoding": "utf-8",
  "bom": false,
  "delimiter": ",",
  "lineEnding": "CRLF"
}
```

Логическая строка:

```text
{resolvedPrefix}{A}={firstBMarker},{weight},{B1};{nextBMarker},{weight},{Bn}
```

При пустом `regionCode` значение `resolvedPrefix` равно
`null/$ & null/$ & null/$ &`. Для `regionCode: "D29"` используется
`null/$ & null&D29$&`.

CSV всегда содержит одно поле. Запись выполняется стандартным CSV writer с
минимальным quoting.

## Сессия и владение

Клиент передает случайный идентификатор в `X-Session-ID`. Загруженные файлы,
задания, отчеты и результаты принадлежат этой сессии. Объект другой сессии
возвращает `404`, поэтому API не раскрывает факт его существования. Файловые
пути наружу не возвращаются.

## HTTP API

Все ошибки имеют форму:

```json
{
  "detail": {
    "code": "INVALID_B_NUMBER",
    "message": "В строке 153 отсутствует корректный B-номер",
    "sourceRow": 153
  }
}
```

### `POST /api/uploads`

Multipart-поле `file`. Ответ `201`:

```json
{
  "id": "opaque-id",
  "name": "input.xlsb",
  "size": 13630,
  "format": "xlsb"
}
```

Формат определяется по содержимому. Ограничения размера, ZIP bomb и
несоответствие расширения проверяются до публикации загрузки.

### `POST /api/uploads/{id}/inspect`

Тело:

```json
{
  "sheet": null,
  "mode": "auto",
  "previewRows": null
}
```

Ответ содержит `sheets`, выбранный `sheet`, `mode`, `columns`,
`suggestedAColumn`, `suggestedBColumn`, `preview` и предварительную статистику.
При `previewRows: null` (значение по умолчанию) `preview` и статистика содержат
все строки с данными выбранного листа. Положительное число оставляет возможность
явно запросить ограниченный фрагмент для API-клиентов.
Для Excel лист выбирается по совпадению заголовков/данных, а не по позиции.
Если файл содержит только A-номера, возвращается `sourceHasOnlyA: true`,
`suggestedBColumn: null`, а предварительная статистика отражает замену B на A.

### `POST /api/uploads/{id}/mappings`

Возвращает связки raw- или готового файла для выбора A целиком либо отдельных
B-номеров.
Тело запроса:

```json
{
  "sheet": "AB",
  "mode": "raw",
  "aColumn": 0,
  "bColumn": 1,
  "query": "",
  "offset": 0,
  "limit": 100
}
```

Ответ:

```json
{
  "items": [
    {
      "aNumber": "79299994464",
      "bNumbers": ["79152671935", "79104627540"]
    }
  ],
  "total": 1,
  "offset": 0,
  "limit": 100,
  "mode": "raw",
  "sheet": "AB"
}
```

Поля `query`, `offset` и `limit` позволяют искать по A/B и постранично
загружать до 500 связок. Первый запрос один раз строит дисковый SQLite-индекс
для выбранного листа, режима и колонок; последующие запросы выполняют
индексный поиск по началу A- или B-номера без повторного чтения исходного
файла. Поисковый номер передается в теле запроса и не попадает в URL журнала
доступа. Доступ ограничен текущей сессией.

Чтобы одна A-связка с сотнями тысяч B не создавала чрезмерный HTTP-ответ,
возвращается не более 200 B на один A. В таком случае элемент дополнительно
содержит `bTotal` и `bTruncated: true`; нужный B находится уточнением поиска.
Индекс хранится в приватной директории загрузки и удаляется вместе с ней по
TTL.

### `POST /api/jobs/convert`

```json
{
  "uploadId": "opaque-id",
  "mode": "raw",
  "sheet": "AB",
  "aColumn": 0,
  "bColumn": 1,
  "keepDuplicateB": false,
  "additions": [
    {
      "aNumber": "79772773649",
      "bNumbers": ["79017094611", "79017091445"]
    }
  ],
  "mappingFormats": [
    {
      "aNumber": "79776553528",
      "prefix": "79947013851& null/$ & null/$ &"
    },
    {
      "aNumber": "79917291275",
      "prefix": "null/$ & null&D77$&"
    }
  ],
  "deleteANumbers": ["79299994464"],
  "deleteBCommands": [
    {
      "aNumber": "79990000000",
      "bNumbers": ["79991111111", "79992222222"]
    }
  ],
  "deleteACommandUploadId": null,
  "csv": {
    "encoding": "utf-8",
    "bom": false,
    "delimiter": ",",
    "lineEnding": "CRLF"
  },
  "template": {
    "regionCode": null,
    "firstBMarker": "4:4",
    "nextBMarker": "4",
    "weight": "1"
  }
}
```

Ответ `202`: `{"jobId":"opaque-id","status":"queued"}`.

`additions` добавляются в итоговый файл после чтения исходных данных. Если A
уже существует, новые B объединяются с ним; повторные пары A/B не создаются.

`mappingFormats` задает индивидуальный параметр итоговой строки для выбранного
A-номера raw- или готового файла. Параметр содержит четыре поля, разделенные тремя символами
`&`, и заканчивается на `&`. Для остальных A применяется общий `template`.
В итоговой статистике возвращаются `customFormatsRequested`,
`customFormatsApplied` и `customFormatsNotFound`.

`deleteANumbers`, `deleteBCommands` и `deleteACommandUploadId` позволяют тому
же заданию одновременно удалить целые A и выбранные B. Сначала загружаются
исходные данные и ручные `additions`, затем удаляются B и целые A, после чего
применяются форматы и создаётся один итоговый CSV. Поэтому команды одинаково
работают для исходных и добавленных в интерфейсе связок. Отдельные
`/delete-a` и `/delete-b` сохранены для обратной совместимости API.

### `POST /api/jobs/delete-a`

```json
{
  "uploadId": "opaque-id",
  "mode": "raw",
  "sheet": "AB",
  "aColumn": 0,
  "bColumn": 1,
  "aNumbers": ["79299994464"],
  "commandUploadId": null,
  "additions": [],
  "csv": {},
  "template": {"regionCode": null}
}
```

Список команд дедуплицируется. При наличии `commandUploadId` номера читаются из
первой непустой колонки отдельного файла. Удаление A поддерживает как raw-файл
с выбранными колонками, так и готовый одноколоночный файл.

### `POST /api/jobs/delete-b`

```json
{
  "uploadId": "opaque-id",
  "mode": "raw",
  "sheet": "AB",
  "aColumn": 0,
  "bColumn": 1,
  "commands": [
    {"aNumber": "79299994464", "bNumbers": ["79152671935"]}
  ],
  "additions": [],
  "csv": {},
  "template": {"regionCode": null}
}
```

Для `raw`-файла передаются выбранный лист и колонки A/B. Удаление последнего B
удаляет всю связку A; это отражается в отчете.

### Состояние задания

- `GET /api/jobs/{id}`;
- `POST /api/jobs/{id}/cancel`;
- `GET /api/jobs/{id}/report`;
- `GET /api/jobs/{id}/download`;
- `GET /api/jobs/{id}/preview`.

Состояния: `queued`, `inspecting`, `validating`, `processing`, `exporting`,
`completed`, `failed`, `cancelled`.

`GET /api/jobs/{id}` возвращает:

```json
{
  "id": "opaque-id",
  "status": "processing",
  "stage": "Группировка связок",
  "progress": 63,
  "processedRows": 441000,
  "totalRows": 700000,
  "error": null,
  "summary": null
}
```

## Авторизация

- `POST /api/auth/login` — вход по `email` и `password`, возвращает bearer-токен;
- `GET /api/auth/me`, `POST /api/auth/logout`,
  `POST /api/auth/change-password` — текущий пользователь и его сессия;
- `GET /api/auth/users`, `POST /api/auth/users`,
  `PUT /api/auth/users/{id}` — управление пользователями, доступно только
  суперюзеру.

Все рабочие API, кроме `/api/health` и `/api/auth/login`, требуют заголовок
`Authorization: Bearer {token}`. Методы мастер-файла дополнительно проверяют
роль суперюзера или разрешение `canAccessMaster`.

## Мастер файл

Все методы требуют `X-Session-ID`. Сам мастер-файл общий для локального
экземпляра приложения; идентификатор сессии используется для владения
предложением на слияние и аудита.

- `GET /api/master/lock` — текущее состояние эксклюзивной блокировки:
  `ownedByCurrentUser` (тот же пользователь), `ownedByCurrentSession`
  (текущая bearer-сессия), логин владельца и время занятия. Напоминания
  видны любому входу владельца на странице мастер-файла; отдельного
  колокольчика в портале нет;
- `POST /api/master/lock` — занять свободный мастер-файл. Повторный запрос
  владельца идемпотентен; если файл занят тем же пользователем в другой
  сессии — блокировка перехватывается в текущую;
- `DELETE /api/master/lock` — освободить мастер-файл. Владелец может снять
  блокировку из любой своей сессии; суперпользователь — с `?force=true`;
- `POST /api/master/lock/notify` — сохранить in-app напоминание владельцу
  (показывается на странице мастер-файла, не через портальный колокольчик);
- `GET /api/master/records?query=&parameterGroup=&region=&duplicatesOnly=false&invalidOnly=false&invalidStartOnly=false&offset=0&limit=200`
  — текущие активные строки, номер внутренней master-ревизии, количество строк
  и АОН. В интерфейсе ревизия отображается как версия `T2-N`. Параметр
  `parameterGroup` можно повторять; варианты PANI объединяются в группу
  `pani`, комбинации PANI и региона — в группу `pani_region`, региональные
  параметры — в общую группу `region`, остальные группы: `default` и `custom`.
  Числовой параметр `region` также можно повторять для
  множественного выбора конкретных кодов от 1 до 84. `invalidOnly=true`
  оставляет строки, где опорный номер или хотя бы один АОН имеет длину не 11
  символов. Ответ также содержит `invalidANumberCount`, `invalidBNumberCount`,
  `invalidRecordCount`, общие варианты параметров, массив `regionOptions` и
  дубликаты готовых строк, найденные при последнем слиянии;
  `invalidStartOnly=true` оставляет записи, где опорный номер либо АОН не
  начинается с `7`. Ответ содержит счётчики `invalidStartANumberCount`,
  `invalidStartBNumberCount` и `invalidStartRecordCount`. В `query` можно
  передать до 500 опорных номеров и АОН, разделённых пробелами, переводами
  строк, запятыми или точками с запятой; запись попадает в ответ при совпадении
  хотя бы с одним значением;
- `GET /api/master/history?query=&action=&dateFrom=&dateTo=&offset=0&limit=200`
  — неизменяемый журнал со снимками `before`/`after` и вычисленными списками
  `removedBNumbers`/`addedBNumbers`; `dateFrom` включается в диапазон, `dateTo`
  задаёт исключительную верхнюю границу в Unix-секундах;
- `DELETE /api/master/history` — доступный только суперюзеру-владельцу
  блокировки сброс журнала, импортов и номера общей версии до `T2-0`.
  Активные строки, их стабильные ID и комментарии сохраняются как новая
  базовая точка, удалённые soft-delete строки окончательно отбрасываются;
- `POST /api/master/records`, `PUT /api/master/records/{id}`,
  `DELETE /api/master/records/{id}` — ручные изменения. Если `bNumbers`
  отсутствует или пуст, сервис записывает `aNumber` как единственный АОН.
  Необязательное поле `comment` содержит до 1000 символов и версионируется
  вместе со строкой, но не экспортируется в телеком-CSV;
- `DELETE /api/master/records` — полная очистка активных строк одной новой
  ревизией. Доступна только суперюзеру — владельцу блокировки мастер-файла;
  строки удаляются мягко, а снимки до удаления остаются в истории;
- `POST /api/master/records/batch-delete-a` — удалить выбранные опорные номера;
- `POST /api/master/records/batch-delete-b` — удалить АОН во всех активных
  связках;
- `POST /api/master/records/batch-delete-b-scoped` с `aNumbers` и `bNumbers` —
  удалить АОН только у перечисленных опорных номеров; ответ содержит
  `notLinkedBNumbers` — АОН, не найденные ни в одной из выбранных связок;
- `GET /api/master/export` — актуальный одноколоночный `master.csv`.

Список и история доступны в режиме просмотра без занятия мастер-файла.
Анализ импорта, слияние, экспорт, добавление, изменение и удаление требуют
блокировки текущим пользователем. При отсутствии блокировки API возвращает
`423 MASTER_LOCK_REQUIRED`, при владении другим пользователем —
`423 MASTER_LOCKED` с его логином.
Удаление или истечение строки `auth_sessions` каскадно удаляет блокировку,
поэтому `/api/auth/logout`, истечение авторизации, сброс пароля и деактивация
пользователя освобождают мастер-файл без отдельного запроса.

Анализ слияния:

```json
POST /api/master/imports/analyze
{
  "uploadId": "opaque-id",
  "mode": "auto",
  "sheet": null,
  "aColumn": 0,
  "bColumn": 1
}
```

Первый ответ возвращает долговечный `importId`, `status`, `progressRows`,
`progressPhase` и `maxRows`. Состояние опрашивается через
`GET /api/master/imports/{importId}`; активный после перезагрузки страницы
импорт можно найти через `GET /api/master/imports/active`. При статусе
`analyzed` ответ дополнительно содержит `baseRevision`, статистику `new`,
`unchanged`, `conflict`, `masterOnly`, `sourceRows`, `uniqueA`, `duplicateA`,
`invalidRows`, `skippedRows`, группы повторяющихся опорных номеров и
предпросмотр отличий. Превышение `CAROUSEL_MAX_MASTER_ROWS` завершает анализ с
`MASTER_ROW_LIMIT`; строки никогда не обрезаются молча.

Новые строки выдаются постранично:

```text
GET /api/master/imports/{importId}/items?status=new&offset=0&limit=200
```

`limit` не может превышать 200. Ответ содержит `total`, `offset`, `limit` и
полные входящие записи. До слияния запись можно изменить:

```json
PUT /api/master/imports/{importId}/items/{itemId}
{
  "aNumber": "79000000001",
  "bNumbers": ["79100000001"],
  "sourcePrefix": "79990000001& null/$ & null/$ &"
}
```

После изменения строка повторно классифицируется как новая, совпадающая или
конфликтная, а статистика анализа обновляется. Числовой параметр PANI в первом
поле `sourcePrefix` должен состоять ровно из 11 цифр. Поддерживается совмещённый
параметр вида `79990000001& D29$&null&`: PANI содержит 11 цифр, код региона —
целое число от 1 до 84.

Подтверждение:

```json
POST /api/master/imports/{importId}/merge
{
  "conflictStrategy": "selected",
  "replaceConflictItemIds": ["opaque-item-id"]
}
```

`conflictStrategy`: `keep_all`, `replace_all` или `selected`. Новые строки
всегда добавляются, совпадающие пропускаются, отсутствующие во входящем CSV
master-строки сохраняются. Если master-ревизия изменилась после анализа, API
возвращает `409 MASTER_CHANGED`.

## Отчет

Отчет — UTF-8 CSV со столбцами `source_row`, `code`, `message`,
`masked_a`, `masked_b`. Значения, начинающиеся с `=`, `+`, `-` или `@`,
экранируются от formula injection. Полные номера в отчетах об ошибках и логах
не записываются.
