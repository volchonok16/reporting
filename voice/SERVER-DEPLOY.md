# Инструкция для специалиста по размещению приложения

## Функциональное назначение

«Карусель» — закрытое веб-приложение для обработки файлов со связками
«опорный номер — АОН» и ведения единого мастер-файла.

Приложение позволяет:

- загружать CSV, XLSX, XLS и XLSB в сыром или уже сформированном формате;
- определять структуру файла и выбирать листы и колонки с номерами;
- добавлять и удалять АОН, удалять опорные номера и выполнять массовые
  изменения;
- назначать параметры строк, включая PANI, код региона и
  «PANI + код региона»;
- предварительно проверять результат и формировать итоговый CSV;
- вести мастер-файл: добавлять, редактировать, искать, фильтровать и удалять
  связки;
- импортировать изменения в мастер-файл с анализом различий и конфликтов;
- вести версии, журнал изменений и блокировку параллельного редактирования;
- экспортировать мастер-файл;
- авторизовывать пользователей и разграничивать доступ к мастер-файлу.

## Архитектура и стек

Приложение состоит из двух контейнеров:

1. **Web-интерфейс**

   - Node.js 22;
   - Next.js 16;
   - React 19;
   - TypeScript;
   - Vinext, Vite;
   - внутренний порт `3000`.

2. **API и обработка файлов**

   - Python 3.12;
   - FastAPI;
   - Uvicorn;
   - OpenPyXL, xlrd и pyxlsb для Excel-файлов;
   - локальные фоновые обработчики заданий без внешней очереди;
   - внутренний порт `8000`.

Данные хранятся в SQLite и локальном каталоге `data`. Внешняя база данных,
Redis, RabbitMQ, Kafka, S3 или отдельный файловый сервер приложению не нужны.
Контейнеры запускаются через Docker Compose, работают от непривилегированного
пользователя и имеют встроенные healthcheck-проверки.

## Что находится в архиве

Архив содержит всё необходимое для сборки и запуска самого приложения:

- исходный код web-интерфейса и API;
- Dockerfile для обоих контейнеров;
- `docker-compose.yml`;
- зафиксированные версии Node.js- и Python-зависимостей;
- пример переменных окружения `.env.example`;
- очищенную SQLite-базу с сохранёнными пользователями авторизации;
- документацию и автоматические тесты.

В архиве нет истории обработки, загруженных пользовательских файлов, заданий,
сессий авторизации и записей мастер-файла.

Docker-образы и кэш сторонних библиотек в архив не включены. При первой сборке
серверу потребуется доступ в интернет к Docker Hub, npm и PyPI.

## Что необходимо дополнительно для публичного доступа

На сервере должны быть подготовлены:

- Linux-сервер или виртуальная машина с постоянным диском;
- Docker Engine и Docker Compose v2;
- доменное имя и DNS-записи;
- reverse proxy — Nginx, Caddy или Traefik;
- TLS-сертификат для HTTPS, например от Let’s Encrypt;
- сетевой экран с публично открытыми портами `80` и `443`.

Рекомендуемая схема публикации:

- адрес интерфейса, например `https://app.example.ru`, проксируется на
  `127.0.0.1:3000`;
- адрес API, например `https://api.example.ru`, проксируется на
  `127.0.0.1:8000`;
- порты `3000` и `8000` не открываются напрямую в интернет.

В `.env` необходимо указать публичный адрес API в
`NEXT_PUBLIC_API_URL`, адрес интерфейса в `CAROUSEL_CORS_ORIGINS` и
проверить параметры авторизации. Каталог `data` должен быть постоянным и
доступным контейнерному пользователю с UID/GID `10001`.

Для мастер-файлов до 20 000 000 строк в архиве уже настроены
`CAROUSEL_MAX_MASTER_ROWS=20000000` и максимальный размер загрузки 8 ГиБ
(`CAROUSEL_MAX_UPLOAD_BYTES=8589934592`). На reverse proxy также требуется
разрешить тело запроса до 8 ГиБ и отключить короткий таймаут загрузки, например
для Nginx задать `client_max_body_size 8g` и достаточные
`client_body_timeout`/`proxy_read_timeout`.

Конкретный расход диска зависит от числа АОН и истории. Для верхней границы
20 млн строк рекомендуется начинать минимум со 100 ГиБ свободного постоянного
диска и контролировать его заполнение. Внешняя очередь, Redis или отдельная
СУБД для одного экземпляра приложения не нужны: анализ хранит прогресс в
SQLite, работает пакетами и восстанавливается после обновления страницы или
перезапуска API.

## Итог по комплектности

Для самого приложения в архиве всего хватает: отдельные СУБД, очередь задач,
объектное хранилище или другие прикладные сервисы разворачивать не требуется.

Вне архива специалисту необходимо предоставить только серверную
инфраструктуру публичного доступа: Docker, DNS, reverse proxy, HTTPS и
настройки firewall.
