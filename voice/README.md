# Агент мобильной карусели

Веб-приложение преобразует `.xlsx`, `.xls`, `.xlsb` и `.csv` со связками
телефонных идентификаторов в одно-колоночный CSV, а также точно удаляет целые
связки A или отдельные B. Исходный файл никогда не меняется.

Ключевые свойства:

- закрытый вход по почте и паролю, роли суперюзера и стандартного пользователя;
- суперюзер управляет пользователями и разрешением на доступ к мастер-файлу;
- одна строка результата на уникальный A;
- все B собираются один раз, без накопительных промежуточных строк;
- пустой B становится копией A;
- новые связки A→B можно добавить и удалить прямо в интерфейсе до обработки;
- добавление, форматирование, удаление A и множественный выбор B объединены в
  одном редакторе и применяются одним заданием;
- для отдельных A raw- или готового файла можно выбрать собственный формат строки:
  связанный A слева, код региона или точный ручной параметр;
- код региона необязателен; по умолчанию результат создаётся без него;
- порядок первого появления A и B сохраняется;
- готовый CSV можно повторно импортировать и безопасно редактировать;
- отдельный мастер-файл хранит постоянные ID строк, версии `T2-N` и снимки всех
  добавлений, изменений и удалений;
- эксклюзивная блокировка мастер-файла сохраняет владельца между обновлениями
  страницы, освобождается при завершении авторизации и защищает все изменения
  от параллельной работы пользователей;
- персональный черновик восстанавливает несохранённый редактор или слияние после
  повторного входа либо позволяет пользователю отказаться от продолжения;
- ранее созданный CSV можно проверить относительно исходной базы и применить
  как слияние с отдельным решением по каждому конфликту; новые строки
  просматриваются страницами по 100 и редактируются до подтверждения;
- после формирования можно продолжить редактирование текущего файла либо
  начать с другого;
- готовый CSV можно скачать и подготовить письмо на заданный адрес;
- обработка больших файлов использует потоковое чтение и SQLite spool;
- живой поиск по A и B использует локальный SQLite-индекс и не перечитывает файл;
- задания имеют progress, отмену, отчет и TTL-очистку;
- формулы и макросы не выполняются, номера в логах маскируются.

## Локальный запуск

Требуется запущенный Docker Desktop.

На macOS откройте файл `start-local.command` двойным щелчком или выполните:

```bash
./start-local.command
```

Скрипт сам создаст локальный `.env`, соберет приложение и дождется запуска.
После сообщения «Сервис готов» откройте:

- интерфейс: `http://localhost:3000`;
- API и Swagger: `http://localhost:8000/docs`.

Для остановки откройте `stop-local.command` или выполните:

```bash
./stop-local.command
```

### Ручной запуск через Docker

Если автоматический скрипт не нужен:

```bash
cp .env.example .env
docker compose up --build
```

Остановить:

```bash
docker compose down
```

Временные результаты находятся в Docker volume и удаляются по TTL. Для
production используйте зашифрованный volume, TLS и внешний reverse proxy с
аутентификацией.

## Локальная разработка

### API

Python 3.12+:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

### Web

Node.js 22+:

```bash
npm ci
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

Откройте `http://localhost:3000`.

## Проверка

```bash
.venv/bin/pytest -q
npm run build
npm test
```

Нагрузочный прогон на 700 000 строк:

```bash
.venv/bin/python scripts/performance_test.py --rows 700000 --max-search-ms 500
```

Скрипт выводит время, максимальный RSS, размеры spool/результата, количество
уникальных A/B, время построения индекса и повторного поиска. Нагрузочный тест
не входит в быстрый unit-прогон.

Отдельный контроль мастер-файла на 726 779 строк (включая анализ, группировку
повторных опорных номеров и полное слияние):

```bash
PYTHONPATH=. .venv/bin/python scripts/master_load_test.py
```

Лимит мастер-импорта задаётся `CAROUSEL_MAX_MASTER_ROWS` и по умолчанию равен
20 000 000 строк. Анализ выполняется в фоне с ограниченным потреблением памяти;
обновление страницы не прерывает его.

## Структура

- `app/` — интерфейс Next/Vinext;
- `backend/` — FastAPI, импортеры, бизнес-сервисы и фоновые задания;
- `tests/` — unit, integration, E2E и security/corruption tests;
- `scripts/` — генераторы fixture и performance test;
- `docs/contracts.md` — канонические данные и HTTP API;
- `docs/architecture.md` — компоненты и поток обработки;
- `docs/csv-format.md` — точный логический и физический CSV;
- `docs/user-guide.md` — краткая инструкция пользователя;
- `docs/security.md` — модель угроз и эксплуатационные меры;
- `docs/performance.md` — результаты нагрузочной проверки;
- `docs/known-limitations.md` — ограничения поставки.

## API

Основные операции:

```text
POST /api/uploads
POST /api/uploads/{id}/inspect
POST /api/uploads/{id}/mappings
POST /api/jobs/convert
POST /api/jobs/delete-a
POST /api/jobs/delete-b
GET  /api/jobs/{id}
POST /api/jobs/{id}/cancel
GET  /api/jobs/{id}/report
GET  /api/jobs/{id}/preview
GET  /api/jobs/{id}/download
GET  /api/master/records
GET  /api/master/history
GET  /api/master/lock
POST /api/master/lock
DELETE /api/master/lock
POST /api/master/imports/analyze
POST /api/master/imports/{id}/merge
POST /api/master/records
PUT  /api/master/records/{id}
DELETE /api/master/records/{id}
DELETE /api/master/records
GET  /api/master/export
```

Клиент передает случайный `X-Session-ID`; файлы и задания другой сессии не
доступны. Полные контракты и коды ошибок описаны в `docs/contracts.md`.

## Production

Поставка разделяет web и API. Для одного экземпляра API задания выполняются
ограниченным thread pool, а данные конкретного задания находятся в его
изолированной директории. При горизонтальном масштабировании замените
`JobService` внешней очередью, а временные файлы — приватным объектным
хранилищем. Не запускайте несколько API-реплик с локальным volume как с общим
источником состояния.
