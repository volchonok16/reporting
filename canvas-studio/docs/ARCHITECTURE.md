# Архитектура

Код разделён на слои; каждый зависит только от слоёв под ним.

```
editor     ─ инструменты, панели, команды, хранение          (DOM)
render     ─ граф сцены, вьюпорт, Canvas 2D, экспорт           (DOM / OffscreenCanvas)
components ─ компоненты, экземпляры, варианты, переопределения (чистая логика)
layout     ─ auto layout, ограничения, группы, измерение текста (чистая логика)
geometry   ─ матрицы, прямоугольники, индекс, выражения        (чистая логика)
core       ─ документ, операции, транзакции, отмена, формат    (чистая логика)
```

Пакеты подключаются через `imports` в корневом `package.json` (`#core`, `#layout` и т. д.); в браузере те же имена разрешает import map, которую генерируют `tools/serve.mjs` и `tools/build.mjs`.

## Документ (`core`)

- **Дерево узлов.** Узел — тип (`FRAME`, `TEXT`…), родитель, ключ порядка и свойства. Свойства хранятся разреженно: только значения, отличные от значений по умолчанию для типа (раздел 4 ТЗ).
- **Идентификаторы** вида `<сессия>:<счётчик>`; у каждой сессии редактирования новый случайный идентификатор, поэтому id никогда не повторяются (FR-DOC-005).
- **Порядок соседей** — дробные индексы: строковые ключи, которые сравниваются лексикографически; одновременные вставки не конфликтуют (FR-DOC-006).
- **Операции** — три вида: `create`, `set`, `move`. Удаление — это `set deleted = true`, поэтому его можно отменить и корректно слить с правками других.
- **Правила слияния.** Каждое свойство и место узла в дереве — регистр «последняя запись побеждает» по часам Лэмпорта; перемещение, создающее цикл, отклоняется (FR-DOC-008). Операция `create` идемпотентна, журнал можно проигрывать повторно.
- **Транзакции и отмена.** Транзакция — один шаг отмены. Отмена локальна: откатывает только свои шаги; шаг, который после нас изменил другой участник, пропускается, а пользователь видит уведомление (FR-DOC-010/011). Непрерывные жесты (перетаскивание, ресайз, ввод текста) применяются вживую и записываются одним шагом.
- **Формат файла** — версионируемый JSON-снимок (`canvas-studio/document`, FR-DOC-004).

## Раскладка (`layout`)

Auto layout повторяет CSS Flexbox, чтобы раскладка переносилась в код без интерпретации (FR-AL-006): FIXED, HUG, FILL, PERCENT, FR, min/max в px и %. Ширины вычисляются раньше высот: высота текста и вложенных контейнеров зависит от ширины. После каждой транзакции редактор пересчитывает затронутые деревья раскладки и записывает геометрию в той же транзакции — соавторы, экспорт и отмена видят один и тот же результат.

Текст измеряется через интерфейс `TextMeasurer`: в браузере — настоящим шрифтом (Canvas 2D), в тестах и на сервере — детерминированным приближением.

## Компоненты (`components`)

- **Экземпляр материализован.** Каждый слой экземпляра — обычный узел документа. Он хранит `componentKey` (из какого слоя компонента он получен), `layerKey` (стабильный ключ, FR-CMP-030) и `overrides` — список переопределённых свойств. Поэтому рендер, раскладка, экспорт и синхронизация работают с экземплярами без особых случаев, а соавторы получают обычные операции.
- **Источник слоя.** Корень экземпляра и заменённый вложенный экземпляр берут содержимое из своего `mainComponent`; остальные слои — из своего `componentKey`. Слои сопоставляются по `componentKey`, затем по `layerKey`, затем по уникальному имени — так переопределения переживают смену варианта и замену экземпляра (FR-CMP-031, 040).
- **Переопределение = правка пользователя.** Всё, что пользователь изменил у слоя экземпляра, отмечается в `overrides` и больше не перезаписывается компонентом. Геометрия слоёв внутри экземпляра не переопределяется: её задают раскладка или ограничения компонента; размер корня экземпляра — переопределяемый.
- **Парковка.** При переключении на вариант, где слоя нет, его переопределения сохраняются в `parkedOverrides` экземпляра и возвращаются, когда пользователь переключится обратно.
- **Свойства компонента** (`componentProps`, `propRefs`, `propValues`): «текст» → `characters`, «видимость» → `visible`, «замена» → `mainComponent` вложенного экземпляра.
- **Конвейер транзакции** (`processTransaction`): правки пользователя → отметка переопределений → синхронизация экземпляров (очередь с индексом источников, защита от циклов) → подгонка групп → auto layout. Всё записывается в той же транзакции, поэтому отмена и соавторы видят согласованный результат. Замер: правка компонента с 500 экземплярами по 21 слою — около 150 мс, переопределение одного экземпляра — около 4 мс.

## Стили (`components/styles.ts`)

- **Стиль — узел документа** типа `STYLE` рядом со страницами: имя (папки через «/»), описание, вид (`styleType`: цвет, текст, эффект) и значения в обычных свойствах (`fills`, `effects`, типографика). Поэтому стили получают отмену, слияние правок соавторов, сохранение и вставку без отдельного механизма.
- **Слой хранит и ссылку, и копию значений**: `fillStyleId`, `strokeStyleId`, `effectStyleId`, `textStyleId` плюс сами `fills`, `strokes`, `effects`, шрифт. Рендер, раскладка, экспорт и проверка попаданий о стилях не знают — так же устроен формат Figma.
- **Согласование в конвейере транзакции** (первым шагом, до переопределений): привязка копирует значения стиля в слой; правка стиля переписывает все связанные слои в той же транзакции (один шаг отмены, те же операции у соавторов); прямая правка значения у слоя отвязывает его от стиля; удаление стиля отвязывает слои, оставляя значения. Стиль, выбранный у слоя экземпляра, становится переопределением; правка стиля внутри компонента доходит до экземпляров обычной синхронизацией.
- **Копирование между файлами**: в буфер кладутся используемые стили; при вставке берётся стиль с тем же id, иначе местный с тем же именем и видом, иначе создаётся копия.

## Переменные (`components/variables.ts`, `editor/variables.ts`)

- **Узлы документа**: `VARIABLE_COLLECTION` (имя, режимы; первый режим — по умолчанию) и внутри неё `VARIABLE` (тип, значения по id режима, описание, область применения, имена в коде). Значение — литерал или ссылка `{ type: 'ALIAS', id, opacity? }`. Переименование ничего не ломает: везде хранятся id.
- **Привязка поля** — `boundVariables` у слоя или стиля: «поле → переменная» (`width`, `cornerRadius`, `fills/0`, `effects/1`, `visible`, `characters`…). Описание каждого поля (тип, свойство, область, чтение и запись) — в одной таблице `fieldSpec`, новое поле добавляется одной записью.
- **Значение хранится и в слое.** Как со стилями, рендер и экспорт видят обычные значения. Конвейер транзакции поддерживает копии: прямая правка привязанного значения отвязывает поле (до стилей, чтобы стиль, у которого «перебили» значение, отдал слоям уже без привязки); после синхронизации экземпляров пересчитываются все узлы, которых правка могла коснуться: привязанные в этой правке, перемещённые и созданные, поддеревья со сменённым режимом и все пользователи изменённых переменных (с учётом цепочек ссылок).
- **Режим** выбирается для коллекции на странице, фрейме, группе или экземпляре (`variableModes`) и наследуется вниз. Ссылка вычисляется в режиме слоя для коллекции той переменной, на которую ссылается.
- **Стили из переменных**: привязки стиля переносятся в слой вместе со значениями (для обводки `fills/i` → `strokes/i`), поэтому стиль переключается с режимом слоя.
- **Масштаб**: таблица рисует только видимые строки; массовая вставка считает ключи порядка и имена последовательно. 20 000 переменных: вставка ~0,5 с, открытие таблицы ~0,1 с, правка ~5 мс.
- **Токены** (`editor/tokens.ts`): W3C DTCG JSON; `$value` — режим по умолчанию, все режимы, области, имена в коде — в расширении `canvas-studio`. Импорт в два шага: план изменений для просмотра, затем применение одной транзакцией.

## Точность (`geometry/precision.ts`, `editor/snapping.ts`, `editor/precision-overlay.ts`)

- **Чистая геометрия** — в `geometry/precision.ts`: дорожки сеток раскладки, измерения между рамками (Alt), равные интервалы, область обводки с разной толщиной сторон (два контура с правилом чёт-нечет — так её одинаково рисуют холст, SVG и PDF) и формы концов линий. Всё проверяется тестами без браузера.
- **Привязка** — `editor/snapping.ts`: цели (края и центры объектов, направляющие, линии сеток видимых фреймов, соседи для равных интервалов) собираются один раз в начале жеста; линия и равный интервал соревнуются, побеждает ближний; без привязки положение округляется до целых пикселей. Порог — 4 px экрана.
- **Направляющие** хранятся в документе (`guides` у страницы и фреймов, у фрейма — в его координатах, поэтому едут вместе с ним). **Линейки, видимость сеток, пиксельная сетка, привязка** — настройки пользователя (`editor.view`), а не документа; приложение хранит их в браузере.
- **Отрисовка оверлеев** вынесена из `canvas-view.ts` в `precision-overlay.ts`: сетки, пиксельная сетка, направляющие, линейки, розовые интервалы, расстояния, лупа пипетки. Пипетка читает пиксели холста до того, как поверх нарисованы оверлеи.

## Секции (FR-CNV-070, 071)

- **Тип `SECTION`** — контейнер со своим размером, заливкой и обводкой, но без обрезки, auto layout и ограничений для детей. Живёт только на странице или в другой секции (`canContain`); фрейм, группа и компонент секцию не принимают — это проверяется в модели, поэтому вставка, перетаскивание и совместная правка не могут нарушить правило.
- **Выделение:** секции на пути к слою всегда «открыты» (`selectableFor`), поэтому содержимое секции ведёт себя как слои страницы. Пустое тело секции не является целью щелчка (`editor.pickable`): там начинается рамка выделения, которая выбирает слои этой секции (`sectionAt`). Саму секцию выбирают по плашке с названием.
- **Захват содержимого:** `adoptIntoSection` после рисования или изменения размера секции забирает слои родителя, лежащие целиком внутри, и отпускает свои слои, оказавшиеся целиком снаружи. Вызывается отдельным шагом того же жеста, чтобы положение слоёв считалось по уже обновлённой сцене.
- **Статус** (`devStatus`) — свойство документа; на холсте это цветная метка у названия, в слоях — фильтр «Готово к разработке». Режим разработчика будет читать то же свойство.

## Прототипы (`editor/prototype/`)

- **Данные** — в документе: `reactions` у слоя (триггер и список действий, как в Figma), `flowStartingPoints` и `prototypeBackground` у страницы. Экран — фрейм или компонент, лежащий на странице или в секции.
- **`model.ts`** — чистая логика без DOM: экраны, потоки, связи, порядок экранов потока и `PrototypeSession`, превращающая триггер в эффекты (переход, ссылка) с историей для «Назад». Покрыта тестами.
- **`controller.ts`** (`editor.prototype`) — правки как шаги отмены и режим вкладки «Дизайн / Прототип». **`overlay.ts`** рисует стрелки, флажки потоков и маркер «+»; ввод остаётся в `canvas-view`. **`panel.ts`** — вкладка «Прототип».
- **`player.ts`** — просмотр. Работает на **собственной копии документа** со своей сценой и рендером: всё, что произойдёт при показе (переменные и смена вариантов в следующих частях), не трогает редактируемый файл и его историю. Тот же просмотр открывается в отдельной вкладке (`?present=<файл>&page=…&start=…`), файл берётся из хранилища браузера. Ссылки открываются только с http, https, mailto и tel.
- **Анимация переходов:** `easing.ts` — свои кривые Безье (Ньютон с запасным делением пополам) и пружина в замкнутой форме, длительность пружины считается по времени успокоения. Переходы со сдвигом рисуют оба экрана каждый кадр со смещением внутри общего «экрана устройства». `smart.ts` сопоставляет слои по пути имён, а просмотр каждый кадр записывает промежуточные значения в свою копию документа (без истории отмены) и рисует её обычным рендером; в конце восстанавливает точные значения. При системной настройке «уменьшить движение» переходы мгновенные.
- **Прокрутка** (`scroll.ts`) тоже пишет в копию документа: детям прокручиваемого фрейма ставятся позиции «база минус смещение» (закреплённые остаются, липкие упираются в верх), поэтому рисование, попадание курсора и умная анимация работают без особых случаев. **Оверлеи** — стек в `PrototypeSession`; верхний перехватывает ввод. **«Изменить на»** меняет `mainComponent` экземпляра в копии и прогоняет обычный конвейер компонентов; анимация — по снимку слоёв до смены. Поведение экземпляра при прокрутке — его собственное, компонент его не переписывает.
- **Логика** (`expr.ts`, `vars.ts`): свой разбор выражений (токенизатор и Pratt-парсер) с позицией каждой ошибки; переменные пишутся по имени `{Имя}`, а хранятся как `{#id}`, поэтому переименование ничего не ломает. «Установить переменную» записывает значение в режим, действующий на экране, в копию документа и прогоняет конвейер — привязанные слои обновляются сами. «Условие» вкладывается до пяти уровней. Рамки устройств (`devices.ts`) рисуются фигурами, пропорционально ширине экрана.

## Сервер (`packages/server`, `apps/server`)

- **Без внешних пакетов:** `node:http`, `node:crypto`, `node:fs`. Код на TypeScript запускается Node напрямую (снятие типов); объявления нужных частей Node — в `types/node-server.d.ts`, без `@types/node`.
- **Хранение** (`storage.ts`): каждая запись — JSON-файл, запись атомарная (временный файл → fsync → rename), записи по одному ключу идут очередью, идентификаторы проверяются строгим шаблоном (выйти за каталог данных нельзя). Аккаунты — `users/`, сессии — `sessions/` (по SHA-256 токена), файлы — `files-meta/` и `files/<id>/snapshot.json`.
- **Вход** (`auth.ts`): пароли — scrypt (N=2¹⁵) с солью; сессия — случайный 256-битный токен в cookie `HttpOnly; SameSite=Lax` (+`Secure` за HTTPS); ограничение попыток входа по адресу и по email; одинаковые ответ и время для существующих и несуществующих аккаунтов.
- **Защита запросов** (`api.ts`, `http.ts`): изменяющие запросы требуют заголовок `X-CS: 1` и своё `Origin` (защита от CSRF); у всех ответов — `nosniff`, `X-Frame-Options`, у страницы — CSP с хешем встроенной карты импортов. Чужой файл отвечает как несуществующий.
- **Доступ** (`access.ts`): роли viewer < commenter < editor < owner; участники и приглашения хранятся в записи файла. Ссылка «для всех» — случайный токен в заголовке `X-CS-Link`; пароль ссылки проверяется один раз (`/share/unlock`), дальше клиент шлёт подпись HMAC (ключ — `data/secret`), так что смена пароля или сброс ссылки отменяют все прежние подписи без хранения сессий. Без аккаунта ссылка даёт только просмотр. Посетитель без доступа получает «не найдено», как для несуществующего файла; токены и списки людей в ответах видят только редакторы и владелец.
- **Комментарии** (`comments.ts`, FEAT-047): обсуждения лежат рядом с документом в `files/<id>/comments.json`, не в CRDT — они не правка макета, их видят и пишут люди без права редактирования. Метка — страница и точка, либо слой и смещение от его угла. Изменение идёт под очередью файла (`FileBlobs.update`), ответ сервера и сообщение `thread` в live-комнату одинаковые, так что автор и остальные обновляются одним кодом (`editor/ui/comments.ts`). После переподключения клиент перечитывает список.
- **Версии** (`versions.ts`, `core/restore.ts`): документ версии сжат (`v<hex>.gz`), картинки — один раз на файл (`b<sha256>`), версии на них ссылаются; восстановление идёт как операции по тем же id (удалённые узлы возвращаются `Transaction.revive`), поэтому проходит через live-комнату. Комната передаёт новичку свой счётчик Лэмпорта (`welcome.clock`): снимок времён не хранит.
- **Без сети** (`editor/offline.ts`, `apps/web/sw.js`): service worker кэширует файлы сборки (список и версия вписываются при сборке), копии серверных файлов и неподтверждённые операции — в IndexedDB; при подключении `LiveSession` отправляет их с `pending`.
- **Только просмотр** (`core/document.ts`): у документа флаг `readOnly` — любая правка (транзакция или жест) откатывается сразу, в историю не попадает, редактор показывает подсказку; служебные изменения (`undoable: false`) работают. Сервер всё равно отклоняет сохранение без прав.
- **Клиент** (`editor/cloud.ts`): `FileBackend` — общий интерфейс для файлов в браузере (IndexedDB) и на сервере. Приложение при запуске спрашивает `/api/me`: нет сервера → работает в браузере как раньше; не вошли → экран входа (можно продолжить без входа). Сохранение с устаревшей версией не перезаписывает чужое: правки уходят в копию «(конфликт …)».
- **Развёртывание**: `tools/deploy/` — сборка, загрузка версии, systemd с песочницей, nginx, Let's Encrypt, ufw, ежедневные копии ([DEPLOY.md](DEPLOY.md)).

## Геометрия и векторы

- **Контуры** (`geometry/vector.ts`): точки с ручками Безье в собственных координатах слоя; фигуры (прямоугольник со скруглениями, эллипс, многоугольник, звезда) переводятся в те же контуры — на этом построены редактирование точек, «Сплющить», экспорт в SVG и PDF.
- **Булевы операции** (`geometry/boolean.ts`): плоское разбиение — все рёбра режутся во всех пересечениях, каждый кусок остаётся, если результат по разные стороны от него различается, и ориентируется так, чтобы результат был слева; куски собираются в контуры. Работает с дырами, несколькими контурами, касаниями, любым правилом заливки. Булева операция в документе живая: результат считается из детей и кешируется (`layout/node-paths.ts`).

## Экспорт

- PNG / JPG / WebP — тем же рендером, что и холст; SVG (`render/svg.ts`) и векторный PDF (`render/pdf-vector.ts`, свой писатель PDF) — собственные сериализаторы дерева слоёв. В PDF текст — точная картинка плюс невидимый Unicode-слой для выделения и поиска; то, что PDF не умеет (тени, размытие, маски, режимы наложения), встраивается картинкой только для этого слоя.
- Несколько файлов упаковываются собственным ZIP-писателем (`render/zip.ts`).

## Рендер (`render`)

- **SceneGraph** кеширует мировые матрицы, границы, порядок отрисовки и пространственный индекс страницы. Кеш инвалидируется по `ChangeSet`: геометрические изменения пересчитывают поддерево, структурные — всю страницу.
- **Renderer** — интерфейс бэкенда. `Canvas2DRenderer` рисует холст и экспорт одним кодом (FR-CNV-005), отсекает невидимое по индексу.
- Оверлеи редактора (выделение, маркеры, направляющие) рисуются поверх сцены в экранных координатах.

## Редактор (`editor`)

- `Editor` — состояние (страница, выделение, инструмент, вьюпорт) и действия. UI никогда не пишет в документ напрямую — только через действия редактора.
- `CanvasView` — ввод на холсте как конечный автомат режимов: ожидание, панорамирование, перемещение, рамка, ресайз, поворот, создание.
- Команды (`commands.ts`) — единый реестр действий: из него строятся горячие клавиши, палитра команд и подсказки. Клавиши сопоставляются по физической клавише, поэтому работают в русской раскладке.
- Панели — обычный DOM без фреймворка; поля читают значения через функции и обновляются после каждого изменения без пересоздания разметки.
- Хранение — IndexedDB с отложенным автосохранением; копирование и вставка — через системный буфер обмена.
