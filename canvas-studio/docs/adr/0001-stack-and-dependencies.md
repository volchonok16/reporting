# ADR 0001. Стек и отказ от внешних зависимостей

Статус: принято, 7 октября 2026.

## Контекст

Заказчик требует, чтобы код был собственным и решение не зависело от внешних факторов: блокировок реестров пакетов, смены лицензий, ухода мейнтейнеров, уязвимостей в цепочке поставок. ТЗ рекомендует ядро на Rust → WebAssembly (раздел 17.9), но первым делом важна работающая основа, которую команда может развивать с первого дня.

## Решение

1. **Язык — TypeScript с «стираемым» синтаксисом** (`erasableSyntaxOnly`): без enum, namespace и параметров-свойств. Такой код превращается в JavaScript простым удалением типов.
2. **Ни одной зависимости.** В `package.json` нет `dependencies` и `devDependencies`.
   - Сборка и dev-сервер: собственные скрипты в `tools/`, типы снимает встроенный `node:module.stripTypeScriptTypes`.
   - Модули в браузере: нативные ES-модули и import map, без бандлера.
   - Тесты: встроенный `node:test`.
   - UI: собственные DOM-помощники вместо фреймворка.
   - Проверка типов: `tsc`, если он установлен на машине разработчика. Это необязательный инструмент: код собирается и работает без него.
3. **Ядро изолировано.** Пакеты `core`, `geometry` и `layout` не обращаются к DOM и общаются с остальным через сериализуемые операции. Их можно перенести на Rust/WASM, не меняя API для редактора.
4. **Рендер за интерфейсом.** Первый бэкенд — Canvas 2D: он работает везде, используется для экспорта и как запасной вариант (FR-CNV-006). WebGL 2 / WebGPU-бэкенд реализует тот же интерфейс `Renderer`.

## Последствия

- Установка проекта — это копирование папки. `npm install` не нужен.
- Всё, что обычно берут из библиотек (дробные индексы, пространственный индекс, вычисление выражений, раскладка), написано и покрыто тестами внутри проекта.
- Сложные области, где своя реализация дорога (растеризация шрифтов, декодирование изображений), используют платформу — браузер или ОС, а не сторонние пакеты.
- Перенос ядра на Rust — отдельное решение (ADR 0002), когда профилирование покажет узкие места.
