# Серверная приёмка Dogtags Manager в Reporting

Все команды выполняются на сервере из корня репозитория в Bash. Для закрытого контура выберите `offline-tunnel`; для установки с доступом к зависимостям — `prod`.

## 1. Состав и состояние сервисов

```bash
source scripts/resolve-compose.sh offline-tunnel
"${COMPOSE[@]}" ps -a
"${COMPOSE[@]}" logs --tail 100 dogtags-init dogtags-api dogtags-worker dogtags-dispatcher
```

`dogtags-init` должен завершиться с кодом 0; API, PostgreSQL и RabbitMQ — быть healthy. Worker и dispatcher должны работать. Backend, frontend, Voice, Симметрика, PostgreSQL Reporting и MinIO также должны быть запущены.

## 2. Разделение ресурсов

Проверьте конфигурацию развёртывания без раскрытия секретов:

```bash
"${COMPOSE[@]}" config --quiet
"${COMPOSE[@]}" ps
```

У сервисов `dogtags-*` не должно быть опубликованных host-портов. База данных, очередь и volumes Dogtags должны отличаться от ресурсов Reporting, Voice и Симметрики. Только Reporting backend и API Dogtags используют gateway-сеть; private-сеть предназначена для компонентов Dogtags. Остальные сервисы не должны зависеть от успешного старта API Dogtags.

В образе Reporting backend остаются зависимости Reporting и Carousel. Backend Dogtags запускается своим образом: одинаковые имена Python-пакетов и таблиц не означают общий процесс или общую базу данных.

## 3. Вход, маршруты и данные

Откройте `https://t2product.ru`, войдите в Reporting и выберите Dogtags Manager. Второй вход не требуется. Интерфейс должен загружаться через `/dogtags-manager/`, запросы — через `/api/dogtags-manager/`. Без сессии Reporting API вкладки должен отвечать 401/403.

Cookie Dogtags ограничена путём `/api/dogtags-manager`. Собственные browser storage-ключи используют префикс Dogtags. Интерфейс находится в iframe, поэтому его CSS не применяется к другим вкладкам. Общие домен, тема и вход Reporting являются частью интеграции.

Обработайте синтетический файл, дождитесь завершения и скачайте результаты. Проверьте предупреждения и общий архив. При обновлении существующей установки убедитесь, что прежние записи и исходники доступны. Не используйте рабочие файлы для первичной приёмки.

## 4. Остальные приложения

| Раздел | Что проверить |
| --- | --- |
| ЗНИ | загрузка таблицы и фильтров |
| Продукты | загрузка списка и раскрытие продукта |
| Статус продукта B2B | загрузка данных и истории |
| Госинициативы | загрузка реестра и истории |
| Симметрика | открытие редактора через SSO и списка файлов |
| Доска | открытие своей/общей доски и чтение данных |
| Staffing | загрузка оргструктуры и сотрудников |
| Планирование | загрузка проектов и календаря |
| Voice | вход через SSO и открытие редактора Carousel |

Проверку внешних интеграций TFS, Google Sheets и SMTP выполняйте с серверными настройками этих систем. Доступность страниц и отсутствие пересечений с Dogtags сами по себе не подтверждают работу внешних источников.

## 5. Отказ одного модуля

В согласованное окно проверки можно остановить только `dogtags-api`, убедиться в доступности остальных вкладок и восстановить его:

```bash
"${COMPOSE[@]}" stop dogtags-api
# Проверьте Reporting и Voice; Dogtags должен показать недоступность своего API.
"${COMPOSE[@]}" start dogtags-api
```

После восстановления обновите состояние вкладки Dogtags. Проверка не требует остановки баз данных, очереди или других приложений.

## Ограничения выпуска

Фактическая приёмка `t2product.ru` и проверка полного общего bundle на архитектуре сервера ещё требуются. Исходные domain-тесты Dogtags имеют известный результат 227 passed / 29 failed; те же ошибки воспроизводились до переноса. Общий TypeScript-check Reporting также имеет ранее обнаруженные ошибки. Этот документ описывает серверную процедуру и не является подтверждением уже выполненной выкладки.

## Результат проверки совместимости перед выпуском

27 ноября 2026 выполнено 6 deployment-тестов, включая сравнение всех прежних сервисов при включении Dogtags в prod/offline/corp-direct, раздельные mounts/сети/порты и сохранение запуска старого Reporting при выключенном модуле. Проверены синтаксис и фактические HTTP/HTTPS-ответы nginx на всех шести шаблонах: Dogtags допускает заявленный размер 51 MiB, общий API сохраняет предел 50 MiB, маршрут Voice сохраняет свой отдельный лимит. До исправления HTTPS-шаблоны не проходили nginx -t из-за повторного client_max_body_size; HTTP отклонял такие запросы Dogtags с 413.

В контрольном Docker-окружении успешно ответили API ЗНИ, Продуктов, Госинициатив, Staffing, Планирования, Voice и Dogtags, MinIO; прошли SSO Voice и Симметрики. Из контейнеров Voice и Симметрики имя внутреннего API Dogtags не разрешается. Общих mounts данных с остальными сервисами нет. Все вкладки открыты в браузере.

Полная функциональная приёмка B2B и Доски ограничена настройками контрольного окружения: в B2B пуст справочник офисов (503), а тестовая учётная запись не привязана к org_user, требуемому Доской (401). Эти условия не связаны с Dogtags и должны быть проверены на сервере с его данными и учётной записью сотрудника. Проверки не подтверждают фактический статус работающего t2product.ru.
